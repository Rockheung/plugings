# comment-journey-strip — 주석에서 여정을 걷어내고 결론만 남긴다

주석이 길어지는 이유는 대개 **작성자가 자기 여정을 적었기 때문**이다. "예전엔 X 였다",
"실측으로 뚫렸다", "그래서 갈랐다" — 읽는 사람은 그 과정을 묻지 않았다. 묻는 것은 하나다:
**이 코드가 왜 이렇게 생겼나.**

여정은 커밋 메시지·PR 본문·KB 에 남긴다. 코드에는 결론만 남긴다.

## 판정: 주석 한 덩이를 셋으로 가른다

| 종류 | 판정 | 처리 |
|---|---|---|
| **불변식·함정** | 이걸 모르면 다음 사람이 코드를 부순다 | **남긴다** (원문 유지) |
| **실측값** | 숫자가 결론을 지탱한다 (측정 55s · 200경로 중 3곳) | **한 줄로** 남긴다 |
| **여정** | 무슨 일이 있었는지의 서사 | **지운다** |

셋을 가르는 질문: **"이 문장을 지우면 코드가 왜 이런지 모르게 되나?"**
- 모르게 된다 → 불변식. 남긴다.
- 여전히 안다, 다만 *어쩌다 그렇게 됐는지*를 잃는다 → 여정. 지운다.

## 여정의 표지 (이게 보이면 거의 확실)

- 과거형 사건 서술: `예전엔` · `옛 표면은` · `~였을 땐` · `있었다` · `없었다` · `빠져 있었다` ·
  `드러났다` · `안 됐다` · `뚫렸다` · `실패했다`
- 자기 판단의 기록: `그래서 갈랐다` · `~로 옮겼다` · `처음엔 ~했다` · `한때 여기 ~라고 적었는데 틀렸다`
- 날짜 박힌 결정: `(결정 2026-07-31, 실증 기반)` · `실측으로 확인한 것(2026-08-07)`
- **개명 대조표**: `기존 워딩 → 현행`, `exec→call`, `EACCES→FORBIDDEN`
  → 정본 문서(`NAMING.md` 등)가 있으면 코드엔 **한 줄 포인터만**. 없으면 문서를 먼저 만든다.
- 정당화 장광설: A/B 파급 측정 서사, 대안을 왜 안 골랐는지의 회고, "이 변경이 여는 것이 아니다"

## 레시피: 과거형 사건 → 현재형 근거

여정을 지우되 **근거는 살린다**. 기계적으로 시제를 뒤집으면 대부분 된다.

```
전: 0o711 — traverse 가능, list 불가. 0755 였을 땐 디렉터리 목록만으로 "이 인스턴스가
    무슨 작업을 큐에 물고 있나" 가 드러났다. 옆 디렉터리에 건 차폐를 여기만 빠뜨렸다.
후: 0o711 — traverse 가능, **list 불가**. 열거되면 큐 파일 이름이 "이 인스턴스가 무슨
    작업을 물고 있나" 를 그대로 드러낸다.
```

```
전: `form` 은 여기 있었으나 뺐다. 태그 차단은 스크립트 경로만 덮어 HTML 템플릿의 폼을
    놓쳤다(실측: POST 유출 성공). 판정을 동작으로 옮겨 …
후: `form` 은 여기 없다 — 태그 차단은 스크립트 경로만 덮어 HTML 템플릿의 폼을 놓친다.
    판정은 컨테이너의 `submit` 취소가 한다.
```

```
전: 처음엔 prototype 을 레지스트리로만 잡았다. 그런데 … 실측으로 확인했다: 교체 후
    미등록 대상으로 요청이 실제 나갔다. 그래서 집행의 본체를 옮긴다 —
후: 레지스트리는 생성 시점의 **함수 참조**를 키로 쓴다 — 제3자가 프로토타입을 나중에 교체하면
    집행이 통째로 빠져 미등록 대상으로 요청이 나간다. 그래서 집행 본체를 우리 객체에 둔다.
```

핵심 변환:
- `~였다/했다` → `~다/한다` (사건 → 성질)
- `실측: X 가 뚫렸다` → `(X 가 뚫린다)` 괄호 한 조각으로 축약하거나 삭제
- `A 였는데 B 로 바꿨다` → `B 다 — A 면 <나쁜 일>` (선택지의 결과만)
- 세 문단 서사 → 한 문단. 대개 **첫 문장과 마지막 문장만 살아남는다.**

## 절차

### 1) 범위 정하고 현황 측정
```bash
for f in $(find <scope> -name '*.ts' ! -name '*.spec.ts'); do
  t=$(wc -l < "$f"); c=$(grep -cE '^\s*(//|/\*|\*)' "$f")
  echo "$c/$t $((c*100/t))% $f"
done | sort -t/ -k1 -rn | head -20
```
주석 비율 40%+ 파일이 대개 여정 보유자다. 절대 주석 **줄 수**가 큰 파일부터 손댄다.

### 2) 여정 전수 탐지
```bash
grep -rnE '^\s*(//|\*).*(예전|옛 |였을 땐|있었다|없었다|드러났다|빠뜨|실측|처음부터|처음엔|해소|되살|그래서 |바꿨|고쳤)' \
  <scope> --include='*.ts' | grep -v '\.spec\.ts'
```
한 번에 워크리스트가 나온다. 파일별로 묶어 큰 것부터.

### 3) 파일별로 읽고 고친다
주석 맵을 먼저 뽑아 어디에 덩어리가 있는지 본다:
```bash
grep -nE '^\s*(//|\*|/\*)' <file> | sed -n '1,120p'
```
그다음 해당 구간만 Read → Edit. **덩이 단위로 통째 재작성**한다(한 줄씩 깎으면 문맥이 깨진다).

여러 파일에 같은 패턴이 흩어져 있으면 python 일괄 치환이 빠르다 —
단, `assert s.count(old) == 1` 로 유일성을 강제할 것:
```python
for path, old, new in edits:
    s = open(path).read()
    assert s.count(old) == 1, (path, s.count(old))
    open(path,'w').write(s.replace(old, new))
```

### 4) 주석만 건드렸음을 **증명**한다 (필수)
```bash
git diff -U0 -- <scope> | grep -E '^[+-]' | grep -vE '^(\+\+\+|---)' \
  | grep -vE '^[+-]\s*(//|\*|/\*)' | grep -vE '^[+-]\s*$'
```
**출력이 비어야 한다.** 한 줄이라도 나오면 코드를 건드린 것이다 — 되돌린다.

### 5) 그래도 돌린다
타입체크 · lint · 테스트. 주석만 고쳤어도 돌린다 —
블록 주석 종결자(`*/`)를 잘못 지우면 파일이 통째로 죽고, 그건 diff 로 안 보인다.

## 함정

- **`eslint-disable` 주석을 지우지 말 것.** 주석 모양이지만 코드다. `// eslint-disable-next-line`,
  `@ts-expect-error`, `oxlint-disable`, `prettier-ignore` 는 전부 남긴다.
- **JSDoc 태그를 지우지 말 것** — `@param`·`@deprecated`·`@type` 은 툴이 읽는다.
- **`⚠` 로 시작하는 반증 경고는 남긴다.** "여기를 지우면 방어가 사라진다고 오해하기 쉬운데 실제
  방어는 저기다" 류는 여정처럼 보이지만 **다음 사람이 잘못 지우는 것을 막는 불변식**이다.
- **스펙 파일 주석은 뒤로.** `.spec.ts` 는 대개 주석 비율이 낮고, 헤더가 그 스펙이 무엇을
  증명하는지를 말한다 — 그건 결론이다.
- **한 덩이를 지우기 전에 그 안에 사실이 하나뿐인지 본다.** 여정 세 문단 속에 불변식 한 줄이
  섞여 있는 경우가 흔하다. 통째로 지우면 그것까지 잃는다.

## 어디로 옮기나 (지운 여정의 행선지)

- **왜 이 변경을 했나** → 커밋 메시지
- **무엇이 바뀌었나** → PR 본문 (단, 과정·삽질·가설 반증사는 PR 에도 안 쓴다)
- **재사용 가치가 있는 검증 기법·반증 사실** → KB / 스킬
- **아무 데도 안 남는 것** → 그건 애초에 남길 가치가 없던 것이다

## 실적 (2026-08-18, [tirno](https://github.com/Rockheung/tirno) `src/`)

10개 파일 · **−55줄 / +44줄** (전부 주석). 코드 라인 변경 0줄(4단계 증명),
tsc·eslint·유닛 190개 통과.

3패스로 수렴했고 그 곡선 자체가 이 스킬의 사용법이다 — **12건 → 2건 → 1건**.
1차는 과거형 사건 서술(`used to print`, `was awaited here and took 55s`, `Verified: …`),
2차는 남은 두 곳 + 파일 간 중복 근거, 3차는 여정 0건. 3차의 1건은 여정이 아니라
`shingle` 대조로 잡은 중복이었다 — 즉 **2패스면 이 스킬의 대상은 소진된다.**

부산물 둘:
- **탐지 grep 은 주석의 언어에 맞춰야 한다.** 2)단계의 한국어 패턴이 영어 주석
  코드베이스에서 0건을 냈다. 0건은 "깨끗하다"가 아니라 "패턴이 안 맞는다"일 수 있다.
- **여정처럼 생긴 자리가 주석↔코드 불일치의 소굴이다.** 여정을 좇다가 설명과 구현이
  어긋난 함수를 찾았다(주석은 "well-known 이름을 순회", 구현은 전량 덤프 파싱).
